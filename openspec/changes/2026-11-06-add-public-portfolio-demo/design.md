## Context

简历访客需要快速理解项目，但真实工作台包含用户会话、上传文档、MCP 配置和会产生费用的模型调用。直接删除登录会破坏现有 tenant 隔离；共享演示账号又会造成访客之间的数据串扰。

## Goals / Non-Goals

**Goals:**

- 匿名访客打开根 URL 后立即看到完整项目说明和主要 CTA。
- 访客可交互切换 Chat、知识库、AIOps、MCP 四个模块的导览状态。
- 所有导览内容清楚标明为公开预览，不访问受保护 API。
- 真实工作台继续通过现有 bearer 会话和路由守卫保护。

**Non-Goals:**

- 本阶段不创建临时 guest user，不新增共享演示账号。
- 不在公开页面触发 LLM、上传、诊断或 MCP 调用。
- 不伪造日志、证据、引用或工具执行成功状态。

## Decisions

### 独立公开路由

`/` 使用项目介绍页，`/demo` 使用交互式导览页。两者不设置 `requiresAuth` 或 `publicOnly`，因此匿名和已登录访客都可访问。

### 导览与真实工作台隔离

导览只使用前端静态产品说明和非结果型界面示意。页面明确展示“公开预览”“不调用真实服务”，并将真实操作 CTA 指向 `/login`。

### 保留认证投资

`/chat`、`/knowledge`、`/aiops` 和 `/mcp` 的路由守卫不变。认证页提供公开导览返回路径，已登录用户访问认证页时仍返回真实工作台。

## Risks / Trade-offs

- [导览不等于完整实时体验] → 使用清晰 CTA 和架构说明，让访客理解真实能力和安全取舍。
- [静态文案可能与实现漂移] → 使用模块级能力描述，不展示易过期的数量或虚构结果，并增加文本测试。
- [公开页面增加维护面积] → 复用现有 token、图标和响应式断点，不引入新依赖。

## Migration Plan

1. 增加公开介绍和导览页面及路由。
2. 更新认证页返回入口和路由测试。
3. 运行前端类型检查、测试、构建和 OpenSpec 校验。
4. 后续如需真实 guest session，另建包含额度、过期和权限策略的变更。
