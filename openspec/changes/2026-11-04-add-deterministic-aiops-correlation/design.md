## Context

现有工作流能可靠地检索 SOP、调用真实 MCP 工具并保存证据，但根因归纳仍主要依赖最终报告 LLM。参考 Culprit 的“确定性规则先排序、LLM 只解释”、aiops-agent 的“代码控制路由和安全边界”，本次变更在报告前增加一个不调用模型的关联层。

## Goals / Non-Goals

**Goals:**

- 相同告警和证据必须产生相同候选与排序。
- 每个候选必须公开匹配规则、信号来源、关联证据和可解释分数。
- 候选必须进入现有步骤、证据、checkpoint 和报告生命周期。
- LLM 失败时仍保留确定性分析结果。

**Non-Goals:**

- 不在本次变更中实现告警聚类、服务拓扑因果推断或自动修复。
- 不把规则分数描述为统计概率。
- 不新增前端页面、API 字段契约或数据库表。
- 不允许仅凭 SOP 文本确认根因；SOP 只提供弱支持。

## Decisions

### 在工作流中增加 Correlator 节点

终止执行后进入 `Correlator`，再进入 `Report`。Correlator 读取查询、告警、SOP 命中和已持久化执行证据，通过纯函数生成最多五个候选。

### 使用声明式签名规则

首批规则覆盖 CPU、内存/OOM、连接池、磁盘、网络、超时/延迟、部署回归和训练工作负载异常。每条规则包含中英文强特征词，不使用通用的单独 `error`/`异常` 作为根因依据。

### 分数表示证据覆盖，不表示概率

查询、告警、真实执行证据和 SOP 分别提供有上限的权重。候选必须至少命中告警或成功执行证据；仅命中用户查询或 SOP 不会产生候选。分数只用于同一诊断中的候选排序。

### LLM 只能解释候选

报告 Prompt 明确禁止创造候选列表之外的已确认根因。若候选为空，或候选只有告警信号而缺少工具证据，报告必须使用“待验证”或“证据不足”措辞。

## Risks / Trade-offs

- [固定签名无法覆盖未知故障] → 未命中时保留原始证据并明确无法确认，不用宽泛规则制造假阳性。
- [关键词可能产生语义误判] → 要求候选关联到告警或真实工具证据，并公开匹配信号供人工审查。
- [规则维护成本增加] → 规则保持纯数据结构和纯函数，新增规则必须附带正反例测试。
- [报告上下文增加] → 候选限制为五个，信号和证据 ID 均有数量上限。

## Migration Plan

1. 增加纯确定性关联模块和单元测试。
2. 将 Correlator 接入 LangGraph，并更新报告与回退报告。
3. 更新诊断规格和 README，运行后端及 OpenSpec 验证。
4. 无数据库迁移；回滚可移除节点并恢复 Replanner 到 Report 的边。
